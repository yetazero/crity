# Crity 2.9.8

Цветные цифры урона и HUD здоровья цели для Hytale **0.7.0-PRE-1** (`0.7.0-pre.1`).

## Сборка

Нужны JDK 25 или новее и локальный `HytaleServer.jar`.

```bash
bash rebuild-crity.sh
bash check-combat.sh
```

Первый скрипт собирает `target/Crity-2.9.8.jar`, второй запускает проверки.
Для них нужны Kotlin CLI 2.4.10 и Python 3. Пути переопределяются переменными
`HYTALE_SERVER_JAR`, `KOTLINC`, `KOTLIN_STDLIB`, `JAR`, `JVM_TARGET`.

Альтернативная Gradle-сборка с Kotlin 2.4.10:

```bash
bash build.sh
```

Результат: `build/libs/Crity-2.9.8.jar`. Проверено с Gradle 9.7.1 и JDK 26.
Задача `checkCombat` запускает проверки через точку входа Kotlin; JUnit не используется.
Серверный JAR используется только при компиляции и тестах, в мод он не включается.

## Установка

Выйди из мира или останови сервер, затем:

```bash
bash rebuild-crity.sh install
```

Скрипт сохранит предыдущий `Crity.jar` и установит новую сборку в
`~/.local/share/Hytale/data/pre-release/Mods/Crity.jar`.
Другую папку можно задать через `HYTALE_MODS_DIR`. После установки запусти мир заново.

## Команды

- `/crity` — текущие настройки.
- `/crity damage on|default|off` — цветные цифры, стандартные белые или выключение.
- `/crity health on|default|off` — HUD цели, штатная полоса над целью или выключение.
- `/crity debug on|off` — диагностика собственных попаданий в серверном логе.

Команды доступны игрокам и принимают точные значения. Настройки сохраняются
в `crity_players.json` в рабочей папке сервера. Диагностика после перезапуска выключена.
При выключении HUD он скрывается сразу; UI над целью обновляется при следующем попадании.

## Изменения 2.9.8

- Исправлена потеря знака угла: `-25` больше не превращается в `335`.
- Для цветных цифр угол выбирается случайно от -75 до +75 градусов,
  независимо от стороны удара. Направление по Y остаётся вверх.
- В пакете остаётся одна надпись на событие урона, включая `CRIT! 42`.
- HUD работает через `World.scheduleAfter`; устаревшие задачи отбрасываются,
  при удалении HUD и выгрузке плагина таймеры отменяются.
- Настройки разбираются JSON-парсером независимо от пробелов и переносов строк.
  Запись выполняется через временный файл с атомарной заменой, где она поддерживается.
- Убраны разбор команд по подстрокам, неиспользуемые константы, старый Java-порт,
  неупаковывавшаяся папка `assets` и неиспользуемые шаблоны UI.
- Удалены комментарии из кода и скриптов. Shebang в скриптах сохранён.
- Версия сборки и строка запуска плагина берутся из `manifest.json`.

Рабочий шаблон: `src/main/resources/Server/Entity/UI/CrityCombat.json`.
Положительные диапазоны `RandomPositionOffsetRange` применяются в обе стороны;
`HitAngleModifierStrength` влияет на горизонтальное движение.
[Описание API Entity UI](https://docs.hytale.com/assets/entity/ui/).

## Проверка

Проверки охватывают режимы отображения, сохранение прочего UI, цвета, сериализацию,
повторные попадания, единый пакет крита, 4096 случайных углов с обоими знаками,
чтение разных форматов JSON и замену файла настроек.

Перед публикацией проверь в клиенте разлёт в обе стороны, серию ударов одного цвета,
крит, все режимы здоровья, смену цели и выход из мира с открытым HUD.
`/crity debug on` выводит строки `Crity DEBUG hit` с углом и числом отправок.

CRIT по-прежнему определяется эвристикой диапазона урона оружия; это не отдельный
флаг критического попадания движка. Несколько настоящих событий урона не склеиваются.
Автотесты и запуск сервера не подтверждают внешний вид анимации в клиенте.
